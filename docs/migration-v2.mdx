## Overview

`@lobehub/lint` 2.x runs on ESLint 10 flat config. There is no `.eslintrc` and no `.eslintignore`: one `eslint.config.mjs` built with `defineConfig()`, and every other tool reads an ESM config file. lobe-ui is the reference v2 repo.

Agents can do the whole upgrade with the `lobe-lint-v2-migration` skill:

```bash
npx skills add lobehub/lobe-lint
```

The skill lives in `.agents/skills/lobe-lint-v2-migration/` in this repository, with the config codemod in its `scripts/` directory. The commands below use that path; adjust it if your agent installs skills elsewhere.

## Before you start

- Node **20.19 or later** (ESLint 10 supports `^20.19.0 || ^22.13.0 || >=24`; the `>=18` in the 2.1.5 `engines` field is wrong). lobe-ui uses `>=22.22.0`.
- A clean worktree, and the repo's own package manager.

## 1. Run the config codemod

```bash
node .agents/skills/lobe-lint-v2-migration/scripts/migrate.mjs --dry-run .
node .agents/skills/lobe-lint-v2-migration/scripts/migrate.mjs .
```

It has no dependencies, never installs or commits, and a second run changes nothing. It:

- converts the rc files to lobe-ui-style ESM configs and keeps your custom rules, ignores and overrides;
- writes `.releaserc.cjs` and `.changelogrc.cjs` at the root and in every workspace package that has one (`packages/*/.changelogrc.js` that required the root file now requires `../../.changelogrc.cjs`), and replaces an existing `.changelogrc.mjs` and `.releaserc.mjs`;
- bumps `@lobehub/lint` to `^2.1.6`, `eslint` to `^10.12.0`, `stylelint` to `^16.26.1`, `prettier` to `^3.9.10`;
- drops `remark` from the Markdown `lint-staged` entry and `--ignore-path` from scripts;
- leaves husky hooks alone, so repo steps such as `build:toc` stay;
- writes a `TODO(lobe-lint v2 migration)` comment for anything it cannot port, and lists it.

| v1                               | v2                                                    |
| -------------------------------- | ----------------------------------------------------- |
| `.eslintrc.js` + `.eslintignore` | `eslint.config.mjs` (`ignores` in the first argument) |
| `.prettierrc.js`                 | `prettier.config.mjs`                                 |
| `.stylelintrc.js`                | `stylelint.config.mjs`                                |
| `.commitlintrc.js`               | `commitlint.config.mjs`                               |
| `.remarkrc.js`                   | `.remarkrc.mjs`                                       |
| `.releaserc.js`                  | `.releaserc.cjs` (CommonJS, see below)                |
| `.changelogrc.js`                | `.changelogrc.cjs` (CommonJS, see below)              |

Configs must be ESM. `require('@lobehub/lint')` throws `ERR_PACKAGE_PATH_NOT_EXPORTED`.

The changelog and release configs are the exceptions, because the tools that read them silently ignore `.mjs` and fall back to their defaults:

- The release notes plugin (conventional-changelog-gitmoji-config) reads `.changelogrc*` with cosmiconfig 7, which never looks at `.changelogrc.mjs`.
- semantic-release 21 and 22 accept cosmiconfig `^8.0.0`, and a lockfile that resolved 8.0 or 8.1 never reads `.releaserc.mjs` (lobe-icons and lobe-charts: the Release job succeeds but uses the angular defaults, so gitmoji commits never release). Only semantic-release 23+ (cosmiconfig 9; lobe-ui uses 25) always reads `.mjs`.

Use CommonJS with the `@lobehub/lint/*` entries (new in 2.1.6, which fixes this):

```js
// .changelogrc.cjs
module.exports = require('@lobehub/lint/changelog');
```

```js
// .releaserc.cjs (use '@lobehub/lint/release-monorepo' for the monorepo config)
module.exports = require('@lobehub/lint/release');
```

Already on v2 with `.changelogrc.mjs` / `.releaserc.mjs`? Run the codemod again: it replaces them (and the workspace package copies). Then check the next Release log: with the lobe config semantic-release loads `@semantic-release/changelog` and `@semantic-release/git`; the defaults load only `@semantic-release/npm` and `@semantic-release/github`. Before that, `node .agents/skills/lobe-lint-v2-migration/scripts/check-release.mjs` (from the skill) runs semantic-release's own `getConfig` for the root and every workspace package with its own release config (or the dirs you pass) and exits 1 when a config is not loaded; keep a `.releaserc.mjs` only if it passes.

## 2. Install and check the configs load

```bash
pnpm install
npx eslint --print-config src/index.ts > /dev/null
npx stylelint --print-config src/index.ts > /dev/null
```

## 3. Fix

1. `eslint --fix` and `stylelint --fix` on your lint globs.
2. `prettier --write` on the same files. ESLint fixers do not format, so fixed imports can look like `import type {Foo }` (`consistent-type-imports`) or `import { Button, Flexbox  }` (`import-x/no-duplicates` merging two imports) until Prettier runs.
3. Type-check right away. With 2.1.5, autofixes could produce `import type { type A, useMemo }` (TS2206 / TS1361), untyped `({ ref, ...props })` from `@eslint-react/no-forward-ref` (TS7031) and lowercased `${…}` interpolations in `transition` values; 2.1.6 fixes all three. If you ran `--fix` on 2.1.5, upgrade, run `--fix` again and repair what the old fixes already broke.
4. Fix the rest by hand. A local disable gets a reason: `// eslint-disable-next-line no-console -- CLI output`.

Most errors on a fresh migration are autofixable (`consistent-type-imports`, `simple-import-sort`, `perfectionist/sort-*`). `no-console` is not.

### Upgrading from 2.1.5 to 2.1.6

2.1.6 upgrades `@eslint-react/eslint-plugin` (2.x → 5.x) and `eslint-plugin-react-hooks` (5 → 7). Compared with `--print-config` for `.ts`, `.tsx`, `.js`, `.mjs`, `.cjs` and test files (`defineConfig({ react: true })`), only `.jsx` / `.tsx` rules changed. Rules that are new at `error`:

| Rule | Before | Fix |
| --- | --- | --- |
| `@eslint-react/jsx-no-key-after-spread` | `jsx-key-before-spread`, warn | Move `key` before the spread: `<div key="x" {...props} />`. A `key` after a spread makes the automatic JSX runtime fall back to `createElement`. Not autofixable. |
| `@eslint-react/jsx-no-children-prop-with-children` | — | Drop either the `children` prop or the children content (editor suggestion). |
| `@eslint-react/rules-of-hooks` | — | Same check as `react-hooks/rules-of-hooks`, so a violation shows up twice; fixing the hook call clears both. |

Renamed, same level. A disable comment with the old id is now an unused directive (an error), and `--fix` deletes it, so rename it instead:

- `@eslint-react/dom/no-<x>` → `@eslint-react/dom-no-<x>`; `dom/no-namespace` → `jsx-no-namespace`
- `@eslint-react/web-api/no-leaked-<x>` → `web-api-no-leaked-<x>`; `rsc/function-definition` → `rsc-function-definition`
- `@eslint-react/naming-convention/<x>` → `naming-convention-<x>`; `naming-convention/use-state` → `use-state`
- `@eslint-react/hooks-extra/no-direct-set-state-in-use-effect` → `set-state-in-effect` (and `react-hooks/set-state-in-effect`)

Removed: `@eslint-react/no-default-props`, `no-prop-types`, `no-redundant-should-component-update`, `no-string-refs`, `no-useless-forward-ref`, `prefer-use-state-lazy-initialization`.

New warnings: `react-hooks/config`, `error-boundaries`, `gating`, `globals`, `immutability`, `incompatible-library`, `preserve-manual-memoization`, `purity`, `refs`, `set-state-in-effect`, `set-state-in-render`, `static-components`, `unsupported-syntax`, `use-memo` (the React Compiler rules; `error` with `reactCompiler: true`), the `@eslint-react` rules with the same names (except `config`, `gating`, `globals`, `immutability`, `incompatible-library`, `preserve-manual-memoization`, `refs`) plus `@eslint-react/exhaustive-deps` (dropped again in 2.1.7, `react-hooks/exhaustive-deps` stays), `jsx-no-children-prop`, `jsx-no-leaked-dollar`, `jsx-no-leaked-semicolon`, `web-api-no-leaked-fetch` and `web-api-no-leaked-intersection-observer`.

To keep a rule at its old level while you clean up, set it in `eslint.config.mjs` with a reason, e.g. `{ files: ['**/*.tsx'], rules: { '@eslint-react/jsx-no-key-after-spread': 'warn' } }`.

### Upgrading from 2.1.6 to the next release

- The `@eslint-react` copies of react-hooks rules are off, so each violation is reported once by `react-hooks/*`: `error-boundaries`, `exhaustive-deps`, `purity`, `rules-of-hooks`, `set-state-in-effect`, `set-state-in-render`, `static-components`, `unsupported-syntax`, `use-memo`. `--fix` removes disable comments that only named the `@eslint-react/*` id; keep or add the `react-hooks/*` one.
- `@eslint-react/web-api-no-leaked-fetch` is an error. A `fetch` in an effect that is not aborted on cleanup can resolve after a newer request and overwrite its result. Abort it on cleanup:

```tsx
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${id}`, { signal: controller.signal })
    .then((res) => res.json())
    .then(setUser)
    .catch((error) => {
      if (error.name !== 'AbortError') throw error;
    });
  return () => controller.abort();
}, [id]);
```

  The rule only accepts an `AbortController` signal. The `let ignore = false; … return () => { ignore = true; }` pattern from the React docs avoids the race too but is still reported (false positive); switch it to an `AbortController`, which also cancels the request. Not autofixable.

## 4. Default exports

v2 warns on `export default`. The warning does not block the upgrade: keep it, or turn it off in `eslint.config.mjs`:

```js
export default defineConfig(
  { react: true },
  // This library default-exports one component per module.
  { rules: { 'no-restricted-syntax': 'off' } },
);
```

If you set `no-restricted-syntax` yourself with other selectors, re-declare it with only those selectors instead.

## 5. Verify

- `lint`, `lint:style`, `type-check`, `test` and `build` pass with 0 errors.
- A commit goes through the pre-commit and commit-msg hooks without `--no-verify`.

Options for `defineConfig()` are in [@lobehub/eslint-config](/packages/eslint-config). Found a lobe-lint bug? Open an issue with the exact error text and a one-command repro.
